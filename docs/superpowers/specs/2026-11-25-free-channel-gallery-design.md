# 免费渠道广场设计

日期：2026-11-25

## 目标

为普通用户增加独立的“免费渠道”页面，让用户浏览可加入的共享渠道、了解当前用户并发分配情况，并从渠道卡片发起加入和创建 Key。它与现有“可用渠道”（查看访问范围、模型和价格）及“渠道状态”（监控渠道可用性）用途不同，应使用独立路由和导航项。

第一阶段交付可在项目中预览的前端视觉稿，使用明确标注的示意数据。真实渠道目录、并发分配、请求历史聚合和 Key 创建暂不接入后端。

## 用户与主要任务

- 普通用户浏览免费共享渠道。
- 用户查看渠道发布有效期、最近请求表现、最大并发、已加入人数和参与用户名。
- 用户加入渠道并创建 Key；同一用户可以创建多个 Key，但这些 Key 共用该用户被分配的并发份额。

## 页面结构

新增 `/free-channels` 用户端页面和“免费渠道”导航项，不修改现有 `/available-channels` 或 `/monitor` 页面。

页面由标题与说明、简短统计区、搜索/筛选控件、响应式渠道卡片网格组成。桌面端使用三列卡片，窄屏降为两列，手机端单列。卡片采用固定的信息阅读顺序，避免因为用户名数量不同导致操作按钮上下跳动：

1. 渠道图标、名称、平台标识，以及“可加入 / 已加入 / 并发已满 / 已下架”等加入状态。
2. 发布有效期剩余时间。
3. 最近 24 小时请求状态格：24 个小时格，每格代表 1 小时。仅汇总真实用户请求结果，不进行主动探活。成功格为绿色；该小时内出现失败请求则为红色；没有请求则为灰色。悬停或键盘聚焦时展示该小时请求数、失败数和小时范围。
4. 最大并发、当前已加入用户数和平均分配提示。
5. 参与者用户名列表，仅展示用户名，不展示邮箱；列表过长时显示有限数量并提供“另有 N 人”。
6. 主操作按钮“加入并创建 Key”；不可加入时给出明确禁用状态和原因。

## 并发分配呈现

设渠道并发上限为 `C`，当前已加入用户数为 `N`。新用户加入后，用户总数为 `N + 1`，并发在用户之间尽量平均分配。单个用户可以创建多个 Key，但不会因此增加该用户的并发份额。

卡片突出显示“最大并发”和“加入后预计份额”，并用分段并发条表现份额分布。对不能整除的情况展示范围，例如并发 5、加入后共 2 人时显示“每人约 2–3 并发”。本次视觉稿不定义余数的实际分配算法。

## 视觉方向

采用清晰、安静的资源目录风格，匹配现有 Vue、Tailwind、圆角卡片和深浅色主题。通过细腻的边框、克制的阴影、明确的字重与紧凑的数字排版做出质感，不增加大面积渐变或装饰性图案。

| 角色 | 颜色 |
| --- | --- |
| 雾白背景 | `#F3F7F6` |
| 纯白卡片 | `#FFFFFF` |
| 墨绿灰文字 | `#17343A` |
| 分割与边框 | `#DCE6E3` |
| 青绿强调 / 成功 | `#16846F` |
| 请求失败 | `#D65353` |

中文正文使用系统 sans 字体栈；数字、倒计时和并发值使用等宽数字，以便快速对齐比较。暗色模式沿用项目主题变量，不另建主题系统。

页面唯一的视觉记忆点是 24 小时状态格与并发分段条：前者让用户看到真实使用反馈，后者让公平分配一眼可懂。两者使用一致的圆角、间距和低对比背景，避免整张卡片显得像监控控制台。

## 交互与状态

- 搜索按渠道名称筛选；状态筛选至少支持全部、可加入、已加入、并发已满。
- 到期时间清楚区分“即将到期”和普通剩余时间；无截止时间时显示“长期有效”。
- 卡片按钮在当前视觉稿中只演示加入/创建 Key 的确认层，不调用 API、不生成真实密钥。
- 状态格对无请求时段明确显示为空闲，不将其误判为健康或故障。
- 加入状态、请求健康状态、发布到期状态分别呈现，避免用单一颜色承担多种含义。
- 支持键盘焦点、移动端触控和系统减少动态效果偏好。

## 验收标准

- 页面以真实项目布局运行，浅色与深色模式均可读。
- 在桌面、平板和手机宽度下卡片不溢出，状态格和用户名可读，主操作始终易于找到。
- 用户无需阅读说明就能区分请求结果、渠道发布剩余时间和加入资格。
- 示例数据呈现正常、含失败、无请求、临近到期、并发已满等不同卡片状态。
- 明确标示示意数据和非真实创建流程，避免预览稿被误认作已连接线上渠道。

## 范围外

此设计不包含后台发布/编辑渠道的管理界面、真实并发租约与余数调度算法、请求日志聚合 API、实际 Key 创建后端流程或并发规则迁移。这些需要后续单独设计并与后端契约对齐。
